# esheep-whisperme-insight (v2.0)

## Overview

将音频/视频内容高效转录为结构化文字，并依托 Agent 自身的上下文窗口与推理能力，提供**自用伴学**与**商业交付**双驱动工作流。

**核心原则**:
1. **0 额外大模型成本**: 深度内容挖掘与结构化报告完全由 Agent 自身的上下文窗口和推理能力完成，无需配置额外大模型 API Key。
2. **极简意图分流**: 明确意图时 0 交互静默直通；未指定意图时出极简二选一问答卡片。
3. **商业交付品质**: 自动语气词去噪（剔除口头禅），采用出版级排版规范（A4标准边距、双语字体、时码分块、表格交替底纹）。
4. **开箱即用归档**: 商业交付流自动在 `deliveries/【播客名】单集标题/` 下生成完整交付资产，直接可用。

---

## When to Use

- 用户提供播客链接（小宇宙、网易云、喜马拉雅等）或本地音视频文件需要转录与深度分析
- **场景 A（个人自用）**：需要边听播客边和 Agent 讨论，拆解观点、反思假设、答疑解惑
- **场景 B（商业代工）**：受客户付费委托，需要一键自动化将播客转换为标准交付物（Word/MD/SRT 逐字稿 + Word/MD 深度分析报告）
- 用户需要配置或切换 ASR 语音识别服务（云端 API vs 本地免费算力）

## 模式架构：双驱工作流 (Dual-Mode Architecture)

根据用户指令意图，系统分流至以下两种模式之一：

```
                              用户输入 (URL / 本地音视频)
                                          │
                         ┌────────────────┴────────────────┐
                         ▼                                 ▼
                 【意图包含交付/商业词】           【意图未指定 / 个人探索】
                         │                                 │
                         ▼                                 ▼
                  直接直通 Mode 2                  抛出极简问答卡片
                                                           │
                                           ┌───────────────┴───────────────┐
                                           ▼                               ▼
                                     [选 1] 伴学探索流               [选 2] 一键交付流
```

### 模式一：伴学探索流（个人自用）
- **定位**：自用深度吸收、播客共读、听友智库。
- **目标**：不追求机械堆砌文件，而是在对话框中为用户提供**思想碰撞、反常识洞察、逻辑反思与实时答疑**。
- **输出**：对话框内的观点卡片 + 引导性追问 + 随时陪用户边听边聊。

### 模式二：一键交付流（商业代工）
- **定位**：付费代做、知识商业交付、高效批产。
- **目标**：全流程行云流水**零废话一键出件**（下载音频 $\rightarrow$ ASR转录 $\rightarrow$ 文本智能去噪 $\rightarrow$ Agent 深度分析 $\rightarrow$ 格式全量打包归档至目录）。
- **输出**：按规范整理好放入 `deliveries/【播客名】单集标题/` 交付目录下的全套成品。

## 意图路由与问答交互规范

Agent 接收到音频/URL输入时，严格按照以下优先级进行路由：

### 1. 静默直通 Mode 2（一键交付流）
- **触发词**：指令中包含 `交付`、`帮客户做`、`客户需要`、`全自动`、`打包一套`、`一键导出`、`做成交付件`、`docx` 等商业代工意图。
- **交互规范**：**0 冗余确认，立即执行全自动流水线**。直接报告：“已进入一键交付流，正在为您全自动下载、转录并生成交付包...”。

### 2. 静默直通 Mode 1（伴学探索流）
- **触发词**：指令中包含 `边听边聊`、`帮我分析这期`、`探讨一下`、`深挖`、`帮我拆解` 等个人学习探讨意图。
- **交互规范**：直接进入探索流，转录完成后在对话框中抛出核心亮点并开启苏格拉底追问。

### 3. 未指定意图时的轻量问答卡片
- **触发条件**：用户仅输入了一个链接或文件路径，没有任何附带说明。
- **输出标准卡片**（极其干练，不长篇大论）：

```text
🎙️ 已接收音频，请选择本次处理模式：

1️⃣ 伴学探索流（个人自用）
- 转录后在对话中与您共同深挖观点、反思探讨、边听边聊。

2️⃣ 一键交付流（商业打包）
- 全自动流水线：自动转录 + 智能去噪 + 生成全套交付物（逐字稿与深度报告）归档至交付文件夹。

👉 回复 1 或 2 即可快捷启动
```

## 交付格式与预设规则（针对 Mode 2）

1. **客户定制搭配**：
   - 若用户指令中明确提到了搭配需求（例如：“这个客户只需要 docx 格式的逐字稿和总结”），严格按客户要求仅导出指定格式。
2. **默认全量策略（免预设）**：
   - 若用户**未特别说明搭配，默认直接全量生成**：
     - **逐字稿包**：`【单集标题】_逐字稿.docx`、`【单集标题】_逐字稿.md`、`【单集标题】_逐字稿.srt`
     - **总结报告包**：`【单集标题】_AI深度总结报告.docx`、`【单集标题】_AI深度总结报告.md`
3. **交付目录与文档整理**：
   - 自动在根目录下创建独立交付文件夹：`deliveries/【播客名】单集标题/`
   - 文档按名字规范整理，保持干净专业，**不需要**单独搞独立的交付说明 README（所有节目元数据、时长、字数已优雅排版在各文档顶部）。
4. **品牌署名**：
   - 不需要特殊的商业交付品牌署名，保持中立纯净的高级排版。

## 模式一：伴学探索流 执行细节

1. **获取转录数据**:
   - 若任务已在本地 whisperMe 处理，直接从后端数据库读取已有段落；
   - 若为新音频/链接，调用 `scripts/asr_cloud.py` 转录并进行文本去噪。
2. **对话框首屏呈现（思维导图式精粹）**:
   - **核心主旨与一句话价值**（这期节目到底解决了什么问题）；
   - **3 个最反直觉或最有争议的论点**（打破常规认知的地方）；
   - **关键发言人立场速览**。
3. **苏格拉底式追问与陪聊伴学**:
   - Agent 主动抛出 1-2 个极具启发性的批判性思考问题（例如：“嘉宾认为 X 会导致 Y，但其前提假设是 Z，您认为在国内当前环境下这个假设成立吗？”）；
   - 随时接受用户自由提问（如“他们在 35 分钟聊的那个工具叫什么？”、“帮我详细展开一下第二个案例”）。

## 模式二：一键交付流 执行细节（行云流水流水线）

1. **全自动执行流水线**:
   ```
   [1. 解析获取] 自动下载音频并提取单集标题、播客名、时长
          │
          ▼
   [2. ASR转录] 调用云端 API 或本地引擎，输出分段时码数据
          │
          ▼
   [3. 智能去噪] 剔除无意义语气助词（嗯、啊、那个、对对对）
          │
          ▼
   [4. AI深度分析] Agent 上下文调用 references/prompt-templates.md 生成完整报告
          │
          ▼
   [5. 格式化导出] 运行 scripts/delivery_export.py 批量生成所选格式文件
          │
          ▼
   [6. 成果交付] 汇报交付目录路径与生成清单
   ```

2. **导出脚本调用方式**:
   - **通过任务 ID 导出**（已在 whisperMe 中）：
     ```bash
     python .agents/skills/esheep-whisperme-insight/scripts/delivery_export.py \
       --task-id <TASK_ID> \
       --summary-file <SUMMARY_MD_PATH> \
       --formats all
     ```

     ```bash
     python .agents/skills/esheep-whisperme-insight/scripts/delivery_export.py \
       --task-json <TASK_JSON_PATH> \
       --summary-file <SUMMARY_MD_PATH> \
       --formats docx,md,srt
     ```

3. **交付完成汇报模板**:
   流水线跑完后，Agent 用简洁专业的格式汇报：

   ```text
   - 📄 逐字稿（Word 排版）：【单集标题】_逐字稿.docx
   ```

## 文本智能去噪规则（口语助词清洗）

在商业交付和深度分析前，统一执行纯语气词与行内填充过滤：

```python
import re
# 纯语气词整行剔除
FILLER_LINE = re.compile(
    r'^[\s]*(嗯+|啊+|呃+|额+|哦+|唉+|哎+|诶+|对对对|是是是|好好好|'
    r'对的对的|没错没错|就是就是|然后然后)[\s。，、！？.,!?]*$'
)
# 行内高频口头禅弱化
FILLER_INLINE = re.compile(
    r'(?:^|(?<=[。，、！？.,!?\s]))'
    r'(?:嗯+|啊+|呃+|额+|哦+|就是说|那个|然后嘛|对吧|你知道吗|怎么说呢)'
    r'(?=[。，、！？.,!?\s]|$)'
)
```

## 常见失误避坑指南

| 错误倾向 | 正确规范 |
|---|---|
| 遇到明确交付意图还在反复问“你要什么格式” | 除非明确要求某单一格式，默认一律全量（DOCX+MD+SRT），一次性搞定 |
| 商业交付时在文档里塞入个人或 whisperMe 推广署名 | 保持文档中立、专业、干净，尊重客户所有权 |
| 交付流中间步骤停下来让用户按回车或输入确认 | 交付流必须行云流水全自动跑通，直到最终输出交付目录 |
| 自用模式直接甩出 5000 字八股文报告 | 自用模式先给思维导图与反常识亮点，以苏格拉底追问引发探讨 |
| 在根目录下随意散落文件 | 严格归档至 `deliveries/【播客名】单集标题/` 专有文件夹 |
